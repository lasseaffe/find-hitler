## [09:45] Fix Prisma 7 signup crash — driver adapter required

- Root cause: Prisma 7.8.0 generates the `client` (queryCompiler/WASM) engine, which has NO built-in DB connector and REQUIRES a driver adapter. `db.js` called `new PrismaClient({ log: [] })` with no adapter → `PrismaClientConstructorValidationError: Using engine type "client" requires either "adapter" or "accelerateUrl"`. This crashed the `/api/auth/[...nextauth]` route at module eval, blocking all signup.
- The 4 prior fix commits (82e10c5, 398eaa6, b9bd087, db3c0e5) all tried different ways of passing the connection STRING — the `client` engine ignores the URL at the constructor; it needs an adapter OBJECT. That's why they never worked.
- Fix: installed `@prisma/adapter-pg@7.8.0` + `pg`; rewrote db.js to construct `new PrismaPg({ connectionString: process.env.DATABASE_URL })` and pass `{ adapter }` to PrismaClient (inside the singleton guard).
- Verified live: standalone script connected to Supabase pooler and ran `user.count()`/`account.count()` → returned 0/0 (no SSL or missing-table issues).
- Files changed: src/lib/db.js, package.json (+@prisma/adapter-pg, +pg), package-lock.json
